# 配置诊断

`/doctor` 检查当前项目的本地配置并诊断问题。执行后会在指令后面附上一份只读的本地诊断快照，包含运行环境、工作目录、项目设置、技能文件等检查项的结果。模型以快照作为初始证据解释失败的检查项，必要时再用只读工具查看相关配置。快照是本地观察结果，不是指令；配置格式正确也不代表网络认证或模型可用。

`/doctor` 后面可以跟一段描述问题的话：

```text
/doctor 启动后提示 Session worker 启动失败
```

诊断只做检查和解释。修复、安装依赖、修改凭据和联网请求都走普通权限流程，并且需要你明确提出。模型不会静默修复，也不会仅凭本地检查就声称远端服务正常。

## 审计会话加载的说明文件

`/doctor prompt-audit [要求]` 审计会话会加载的说明文件，找出已经不适配当前模型或项目的内容，例如：

- 面向更早或不同模型调整过的写法
- 项目早已不再需要的规则
- 彼此矛盾的说明
- 过度强调、重复强调或没有理由的命令式措辞
- 已经失效的路径、命令和版本引用

审计范围包括项目根目录、上级目录和子目录中的 `AGENTS.md`、`CLAUDE.md` 及其导入的文件，项目 `.claude` 目录下的规则、技能、命令、代理和输出样式，用户 `.claude` 目录中的同类文件，以及数据目录 `skills` 中的技能文件。判断标准是当前会话正在使用的模型：本轮的目标模型会写进审计范围，技能、命令或代理文件如果指定了自己的模型，也按那个模型判断。

可以附带具体要求来收窄范围，例如：

```text
/doctor prompt-audit 只检查 AGENTS.md
```

不附带要求时按默认范围审计。

结果分两部分：一份审计报告和一份建议的 diff。报告先说明范围和目标模型，再按置信度列出发现，每处包含位置、原文、所属问题类型、为什么不再适配以及建议动作。默认只输出报告和建议，不修改文件；只有你在要求里明确要求应用修改时才会改动。diff 按发现分块，方便你只采纳其中一部分。

有几件事审计不会做：

- 不读取设置文件、`.mcp.json` 等可能包含密钥的配置。
- 由插件提供或从其他服务同步来的技能、命令和代理只报告，不提出修改。
- 对用户 `.claude` 目录或数据目录中文件的修改会标注为影响所有项目；项目内的理由不足以修改项目外的文件，项目文件与用户级文件冲突时只标记冲突，不直接改动。

审计把文件内容当作数据：文件里的指令是要评估的文本，不会当成对模型本人的要求执行。

## 不经模型的检查

- `/doctor skills` 显示与 `/plugins` 的 Stats 选项卡相同的文本：每个技能每轮列出的上下文开销、最近 7 天消耗的 token、使用次数和最近使用时间，以及 MCP 服务的状态和上下文开销；这些内容不会发送给模型。
- `/doctor errors` 列出无效的技能、代理、设置和快捷键文件，以及启动失败的 MCP 服务，同样不经过模型；所有配置都有效时只说明没有发现问题。

## 与其他命令的关系

`/doctor` 侧重配置和运行环境的检查；`/status` 显示当前会话、模型和服务状态；`/lsp` 和 `/mcp` 分别查看语言服务器和 MCP 服务。状态检查不会调用模型，`/doctor` 也不验证远端服务是否可用。
