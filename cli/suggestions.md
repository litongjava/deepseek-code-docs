# 建议补全

符合生成条件的一轮结束后，dcl 会预测你接下来最可能输入的话，以灰色文字显示在空的输入框里。合适就按 `Tab` 接受，不合适直接输入别的内容即可。

```text
● Changed 1 file (+1) · Ctrl+O shows the diffs
    hello.py  +1

✻ Brewed for 4s · done 6:15 PM
──────────────────────────────────────────────
❯ now run it
──────────────────────────────────────────────
? for shortcuts · tab to accept suggestion
```

## 操作

| 按键 | 作用 |
|---|---|
| `Tab` 或 `→` | 把建议填入输入框，可以继续修改后再发送 |
| 直接输入 | 建议消失，按你输入的内容为准 |
| `Enter`（未接受时） | 发送空输入，不会发送建议 |

建议只在输入框为空时显示。在建议生成出来之前你已经开始输入的话，它就不会再出现。恢复会话时，仍有效且未接受的最后一条建议会重新显示，无需再请求模型。新的一轮开始后，包括从其他进程继续同一会话时，旧建议会失效。

## 建议从哪里来

主请求成功后，如果供应商报告读到了缓存，或 dcl 识别出支持自动前缀缓存的主机和模型，才会请求建议。dcl 复用刚完成的请求体，在末尾追加一条用户消息，请模型用你的语言和语气预测接下来的输入，例如“运行测试”。下一步不明确时允许留空。系统提示、工具定义和已有输入保持相同，以便提供商复用缓存。自定义代理即使兼容同一协议，也可能需要先报告缓存读取。

生成建议是一次额外的模型请求，实际用量以提供商报告为准。生成须在主请求结束后的五分钟内开始，单次请求最多等待 15 秒。模型返回工具调用、请求失败或没有合适的短句时，输入框保持空白。

## 关闭

在[数据目录](./data-directory.md)的 `config/settings.json` 中设置：

```json
{ "promptSuggestionEnabled": false }
```
