# 工具权限

模型回复文本与调用本机工具不同。文件修改、命令执行、MCP 工具等操作需要结合权限模式理解。

## 权限模式

- **询问权限（ask_permissions）**：界面定义为工具调用需要用户确认，适合初次使用。
- **接受编辑（accept_edits）**：自动接受编辑操作，危险操作仍需确认。
- **计划模式（plan_mode）**：界面定义为只读模式，禁止修改，适合先分析任务。
- **全托管模式（bypass_permissions）**：自动批准操作，适用于明确了解范围的任务。
- **不询问权限（dont_ask）**：执行已授权操作，需要额外审批的操作直接拒绝。

计划审批还可选择自动批准（auto），由后端审批协议应用到本轮执行。Auto 下未命中[危险规则](../../cli/dangerous-commands.md)的 Bash 直接执行，不调用分类器；其他工具仍按 Auto 策略判断。

## 工具审批中的取消（开发版本）

包含此改动的 Desktop 开发版本在工具审批框提供 **Cancel turn**：终止整个回合并撤销待批工具，不再继续该回合的模型请求。**Deny** 只拒绝当前调用，模型仍可收到拒绝结果继续回答。

取消必须等待后端确认停止。确认失败时保留审批提示并显示错误，不能将其视为已经取消。加载过工具不等于授予执行权限，恢复会话后也一样。

## 当前会话 Bash 授权

Bash 审批显示说明和完整命令。未命中危险规则时提供 **Allow for Session**，允许当前运行会话后续非危险 Bash；危险命令仍需逐次确认。此授权不写入项目设置，重连同一个运行中的会话保留，新会话、子会话和应用重启后不继承。

打开输入框的权限菜单可查看 **Session Bash**，点击 **Revoke session Bash permission** 撤销。审批接口拒绝响应时，弹窗保留并显示原因。显式 ask/deny、工具禁用、Hook 与沙箱继续有效。

## 使用 bypass

普通启动即可在权限菜单切换 bypass，也可在计划审批中选择两种 bypass 执行方式：

```powershell
dcd
```

需要直接以 bypass 模式启动时：

```powershell
dcd --dangerously-skip-permissions
```

Windows 快捷方式可以在目标可执行文件后追加直接启动参数。`--allow-dangerously-skip-permissions` 保留兼容，普通启动已经支持切换。默认启动仍保持原有执行模式，不会自动进入 bypass。

计划审批可选择“保留上下文，bypass 执行”或“清理上下文，bypass 执行”，无需先以 bypass 进入 Plan。仍须点击“批准并开始”，计划快照、会话归属及重复审批校验持续有效。清理上下文保留已保存的会话历史。

普通 bypass 继续遵守显式 deny 规则和已配置的沙箱，不启用 Full Access。模式控件只在后端确认后更新。

以上是客户端提供的模式语义，实际操作仍受具体工具和后端规则约束，不应把某模式当作操作系统级沙箱。

## 使用顺序

1. 先选择工作目录。
2. 使用询问权限或计划模式，让模型说明文件与步骤。
3. 工具请求出现时核对工具名、参数、路径和作用。
4. 执行后检查输出和实际差异，再继续下一步。

任务变化时重新确认当前模式，避免沿用上一次任务的设置。

## 浏览器限制

权限组件直接调用 Tauri `invoke('set_permission_mode')`。浏览器里控件改变，不足以证明 Rust 权限已同步。完整权限测试应在桌面端进行。

IM 另有平台访问权限，决定谁能与机器人交互，与本页控制工具行为的权限不同。见[IM 集成](../advanced/im.md)。
