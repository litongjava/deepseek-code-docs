# 通用设置与工作目录

## 首次引导

首次引导依次选择主题、运行模式与工作目录。目录选择按钮在桌面环境中使用原生对话框，普通浏览器不具备相同能力。

完成引导后，到模型设置补充供应商。引导完成不代表已经存在可用模型凭据。

## 外观与输入习惯

设置包含主题、聊天字体、语言以及发送和换行按键。按习惯选择 Enter 发送或 Ctrl+Enter 发送，再在输入框用多行文本确认按键行为。

部分设置保存在当前前端的 localStorage，因此 Chrome 与桌面窗口可能显示不同偏好。

### 聊天阅读与反馈

- 聊天区使用白色或深灰正文背景，用户消息、代码和工具详情以背景区分。输入框有常驻细边框，聚焦时以单圈细线强调；键盘操作保留可见焦点。
- 助手回复默认使用系统无衬线字体栈，聊天默认字号为 14px，助手正文行高为 24px。字号设置由用户消息与助手消息共用；已保存的字号保持不变，旧配置中的 16px 不会自动改成 14px，需要时可在设置中调整。
- 字体选项中的 Default 为助手回复使用系统无衬线字体；Anthropic Serif、Anthropic Sans、System 和 OpenDyslexic 仍可手动选择。默认选项不改变用户消息和输入框原有字体。具体渲染字体取决于系统安装的字体及字符回退。
- 助手正文浅色字重为 400，加粗为 600；一级至三级标题分别为 21/30、19/28、18/26px（字号/行高），字重 700，四级标题为 14/24px、字重 600。调整字号后，助手行高与标题尺寸同步增加或减少。
- 暗色使用减轻 40 的字重请求：正文 360、加粗 560、一级至三级标题 660。非可变字体可能映射到可用字重，不保证精确呈现中间字重。数字使用等宽排列，正文优先使用更自然的换行。
- 行内代码与代码块保留等宽字体，中文注释使用中文字体回退；语法高亮片段不再被正文字体规则覆盖。代码缩进、横向滚动、复制和折叠功能保持原有行为。
- 流式新增正文采用短暂的透明度过渡，文字始终清晰，不使用模糊滤镜。历史内容不会重复播放；同时过渡的字符数量有限，快速到达的其余内容直接显示，不延迟答案。
- 位于底部时，新回复和内容高度变化会自动跟随。向上滚动回看历史后暂停跟随，向下回到底部附近时恢复。切换会话后不会沿用旧会话的滚动任务。
- 工具详情通过 Grid 过渡展开和收起，已打开的内容保留内部状态；收起后内部控件不会进入键盘焦点顺序。代码块展开状态不会因后续回复追加而重置。
- 消息、代码和工具的复制按钮在成功后短暂显示对勾，随后自动恢复。连续复制会重新计时；失败提示保留，可再次点击重试。
- 拖入文件经过输入框内部控件时，提示保持稳定。系统启用“减少动态效果”时，聊天文字和折叠直接显示，复制和拖入反馈不播放弹簧动效。

## 个人资料与账户

通用设置包含姓名、显示名称、工作领域和个人偏好。自托管模式的资料保存到本地；网关模式的部分资料通过账户接口保存。

账户、登录设备、密码和用量等入口可能需要网关。只接入自己的模型服务时，不应把账户页失败当成供应商配置丢失。

登录功能保留但默认禁用，打开应用直接进入自部署界面。后台接口认证失败只在对应功能中报告，不会把本地工作界面跳转到登录页。需要账户登录的部署可以在构建环境设置 `VITE_ENABLE_LOGIN=true` 后重新构建；默认值为 `false`。

## Shell 与 Bash 路径

在“设置 → 通用 → Shell”分别选择模型命令和手动终端使用的 Shell。Bash 路径支持手动输入和桌面文件选择器，留空恢复自动发现；页面显示已保存配置解析到的程序和来源，保存失败会保留输入并显示原因。

这些设置保存到共用数据目录的 `settings.json`，dcl 和 dcd 使用同一份配置。下一条工具命令和新建终端读取新配置，已经运行的终端保持原进程。手动终端选“自动”时，Windows Desktop 继续使用 Windows PowerShell；dcl 的 `!` 命令保留其原有默认值。

选择 WSL 后，点击“查找 WSL 发行版”并明确选择发行版，再填写发行版内的 Bash 路径（默认 `/bin/bash`）。不会自动选择系统默认的 Docker 发行版。WSL 命令的路径转换、取消和沙箱限制见 [Shell 配置](/cli/settings#wsl)。

`DEEPSEEK_CODE_BASH_PATH` 环境变量优先于文件中的 Bash 路径。更改环境变量后，重启应用和 Worker；文件配置不需要重启。

## 请求记录

需要保存实际模型请求、原始响应和压缩记录时，在共用数据目录的 `settings.json` 中配置，见[请求记录](./request-recording.md)。这项设置默认关闭，记录正文不脱敏。

## 工作目录

工作目录决定文件、命令和部分项目工具处理的本地位置。首次使用建议选择范围明确的项目文件夹，并确认自己有读写权限。

引导会保存本地 `workspace_path`，并尝试更新 Bridge 的目录配置。当前引导请求未携带 Bridge 鉴权头，且失败处理较弱，因此不要只凭引导完成就假定后端默认目录更新成功。首次运行文件工具时查看实际目录。

项目名称、项目说明和文件工作目录分别影响组织、上下文与执行位置。创建项目条目不等于工具已切换目录。
