# 自定义入口验证

## 2026-11-07 更新：提示词与工具拆分为两个入口

自定义页原来的“提示词与工具”是一个入口，现在拆分为**提示词**和**工具**。左侧二级导航与概览卡片都按 **Skills → MCP → Connectors → Plugins → 提示词 → 工具** 排列。

- 提示词页只包含系统提示词：使用方式、内置提示词预览，以及替换模式下的内容编辑与恢复。
- 工具页只包含内置工具和自定义工具：每个内置工具的“启用”“按需加载”两个开关、筛选、说明编辑，以及自定义工具的增删改。
- 两页读取同一份设置，**各自保存各自的一半**：在提示词页改了没保存，切到工具页保存不会把它一并提交；反之亦然。保存后下一次模型请求生效，Desktop 与 dcl 共用。
- 没有修改时“保存”不可用；只有提示词页在“完全替换且内容为空”时禁用保存，不会阻塞工具页。
- 两个入口共用一个组件实例，未保存的草稿在切换后仍保留，回到该页可以继续保存。

保存期间切页后，迟到的成功或错误提示也不能显示在新页面，切走再返回原页不会复活旧提示。成功保存仍更新原页面负责的配置，另一页的未保存草稿继续保留。此异步时序由可控 Promise 的组件回归覆盖，不能用“保存已结束再切页”的原生证据代替。

界面文案支持中文和英文。切换语言后，入口名称、页面标题、按钮、表单标签、占位符和提示文字都随之更新；尚未翻译的语言暂时显示英文。

### 真实保存验证

同一实例连接真实 Bridge，直接检查数据目录里的 `customization.json`。为避免留下测试配置，验证前该文件不存在，验证结束后已删除：

1. 提示词页改为“在内置提示词后追加”，填写内容后保存：页面出现“已保存”提示，文件写入 `append` 与对应文本。
2. 工具页关闭内置工具 Write 并保存：文件新增 `disabled_tools`，`system_prompt` 保持步骤 1 的值。
3. 刷新页面后重新打开两页：提示词内容与 Write 的关闭状态都按已保存的值显示，说明读回自服务端而非本地草稿。
4. 在提示词页把内容改成“未保存的修改”但不保存，切到工具页再关闭 Read 并保存：文件里的提示词仍是步骤 1 的内容，只新增了 Read。
5. 反向验证：在工具页把 Grep 关闭但不保存，切到提示词页修改内容并保存，文件中没有 Grep，说明未保存的工具改动不会被提示词页提交。
6. 提示词页切换为“完全替换”并清空内容：“保存”不可用；切到工具页仍可保存，文件中的提示词保持不变。
7. 保存提示只出现在执行保存的那一页，切到另一页不再显示。

截图见 `assets/desktop-customize-prompt-saved.png`、`assets/desktop-customize-tools-saved.png`。

### 原生窗口验证

上面的保存验证在浏览器里完成。为确认原生窗口本身也能保存，另起一个开启了远程调试端口的桌面开发实例，用 deepseek-browser-use 通过 CDP 接手应用窗口本身（`external-cdp`，1920×1032，界面语言为英文），在窗口里实际点击、输入，并逐次检查数据目录的 `customization.json`：

1. 提示词页改为“追加”并保存：文件写入 `append` 与对应文本。
2. 工具页关闭 Write 并保存：只新增 `disabled_tools`，提示词保持步骤 1 的值。
3. 重新加载窗口后回到提示词页：内容仍是保存的值。
4. 工具页关闭 Grep 但**不保存**，切到提示词页修改内容并保存：文件里的 `disabled_tools` 仍为空，Grep 没有被提交，只有提示词变成新值。
5. 提示词页切到“完全替换”并清空，此时提示词页“保存”不可用；切到工具页关闭 Glob，工具页“保存”可用，点击后文件新增 Glob，提示词保持原值。
6. 保存提示只出现在执行保存的那一页，切回提示词页时不再显示。

六项都在原生窗口里实际完成，其中第 4、5 项就是上文“真实保存验证”的反向隔离与空替换提示词场景，没有引用浏览器或组件测试的结论。验证结束后已删除测试写入的 `customization.json`（验证前不存在），界面语言与工具状态未留下改动。

## 2026-11-03 更新：统一概览与管理入口

概览卡片与左侧二级导航均按 **Skills → MCP → Connectors → Plugins** 排列，使用一致的图标容器、标题与描述、尺寸、圆角、箭头及键盘焦点样式。点击概览 Skills 进入技能管理，不再直接创建；需要创建时，在技能管理中点击加号并选择“编写技能指令”。

Skills 读取本地 Bridge 的真实技能列表，按内置与用户技能分组。选择技能可查看内容和启停；用户技能可通过“编辑详情”修改名称、描述和指令并保存。创建后使用后端返回的身份、内容和启用状态；保存后重新读取持久化结果。读取或写入失败会显示错误，不再静默显示空列表或假成功。

MCP 复用现有原生管理页面。变更后同时刷新服务和工具列表；读取错误可重试，保存失败保留表单。配置方法见 [MCP 服务](../configuration/mcp.md)。

本次验证区分两层：

- Skills HTTP 集成测试使用临时数据目录，验证创建、列表、详情、保存、启停、删除及失败状态码，不操作用户技能。
- dsb 有头 Chrome 使用实际页面组件与明确隔离的模拟响应，检查 1664×937 和 1280×800 布局、四项顺序、统一卡片尺寸、Skills/MCP 跳转及 Tab/Enter 焦点导航；两种视口无页面横向溢出。浏览器检查不是原生 MCP 启停或工具调用验收。

开发脚本、测试记录与截图保存在独立开发支持目录；下方截图和统计保留为历史记录。
