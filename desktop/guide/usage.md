# 首次使用

推荐路线：[安装客户端](./installation.md) → [配置模型](../configuration/models.md) → [开始聊天](../usage/chat.md)。之后按需阅读[项目](../usage/projects.md)、[MCP](../configuration/mcp.md)、[Skills](../usage/skills.md)和[知识库](../usage/knowledge.md)。

建议第一次在 Tauri 桌面窗口完成配置和功能验证，浏览器用于补充页面与 HTTP 接口调试。

## 建立第一条对话

1. 启动桌面应用，完成出现的初始化引导。
2. 在设置或模型相关入口中配置供应商、服务地址、模型与凭据。使用自己的服务时选择相应自托管模式；使用网关模式时确认网关服务和账户配置可用。
3. 新建会话，选择模型，发送一条简单文本，例如“请用一句话介绍你自己”。
4. 检查回复是否逐步出现。若一直等待，先查看网络请求和 Rust 日志，不要反复发送相同请求。
5. 切换会话再返回，检查消息是否仍在。

真实模型调用需要有效凭据并可能产生费用；文档站自身不执行这些调用。

## 项目与工具

需要模型读取或修改项目时，先确认当前工作目录。工具请求出现后，阅读具体工具名、目标路径和参数，再按当前权限模式处理。

终端、文件、Git、代码差异和工具执行是不同入口。某个面板能打开，不等于系统依赖、权限、Git Bash 或对应后端已就绪。

## MCP 与 Skills

MCP 连接外部工具服务，需要配置启动命令或服务连接信息。先确认服务能启动，再验证工具列表和具体工具调用。

Skills 提供可复用的任务说明或工具工作流。添加后应通过小范围任务验证其实际行为。

部分 MCP 管理入口仍直接调用 Tauri IPC，因此优先在桌面窗口测试。

## 本地数据与日志

`src-tauri/src/main.rs` 在数据目录（默认 `~/.deepseek-code`，与 CLI 共用）保存 `claude_desktop.db`，知识库放在该目录下的 `knowledge`。启动日志会打印真实数据目录，排查时以日志为准；解析规则见[数据位置](../maintenance/data.md#数据位置)。

日志初始化逻辑将滚动日志写入进程工作目录下的 `logs`。不同启动方式可能改变工作目录。

备份数据库前关闭应用，以免得到不一致的副本。浏览器 localStorage、桌面 WebView 的存储和 Rust SQLite 是不同存储区域，不能互相等同。
