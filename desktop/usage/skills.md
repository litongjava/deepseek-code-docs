# 自定义：技能、MCP、连接器、插件、提示词与工具

Skill 复用任务说明、方法和上下文。MCP 提供工具服务，Skill 描述如何完成任务，两者可以配合。

## 统一入口

从顶部工具栏的“扩展 → 自定义”进入，也可以打开“Settings（设置）→ 自定义”。两处使用同一套页面，包含技能、MCP、连接器、插件、提示词和工具六个入口。

扩展菜单已移除“目录”和独立 MCP 入口；设置中的 MCP 服务也归入“自定义 → MCP”。

![扩展菜单中的自定义入口](/customize-extensions.png)

![自定义页面的入口导航](/customize-overview.png)

## 创建 Skill

在自定义页的 Skills 入口新建条目，填写名称、说明和内容。正文包含适用任务、输入要求、步骤与输出格式。

例如“会议纪要整理”可要求按议题、决定、待办和负责人整理原始记录。不要写入真实账户凭据。

保存后检查详情，用小段示例材料验证格式。

### 使用内置的 skill-creator

Skills 入口的示例区包含内置的 `skill-creator`。它不写入数据目录，展开后显示真实的文件树（`SKILL.md`、`scripts/`、`references/`、`license.txt`、`NOTICE.md`），点击文件可以查看内容。它用于创建和校验新技能，模型会在合适时自动调用；也可以在 dcl 中运行 `/skill-creator`。命令行用法、脚本参数和 frontmatter 字段见 [用 skill-creator 创建技能](/cli/skill-creator)。

旧版本写过一份占位技能。升级后，只有与旧占位完全一致的副本会被移除；改动过或加了文件的副本保持原样。

## 查找与使用

技能从数据目录 `skills/`、`~/.claude/skills` 和项目 `.claude/skills` 读取，同名时项目优先，其次数据目录，最后 `~/.claude`。模型可见的技能列表、`Skill` 工具和斜杠名称使用同一套结果，斜杠命令沿用数据目录的旧命名规则（小写、空格转 `-`，标点保留）。完整顺序、名称与重名规则、`enabled`/`disable-model-invocation` 开关和 `dcl skills list` 的验证方法见[数据目录](/cli/data-directory#技能从哪里读取)。

在列表筛选条目，查看详情和使用入口。项目页也有选择 Skill 的交互。选择后补充本次任务的材料；Skill 不会自动知道未提供的文件内容。

对话输入框的加号菜单里也有 Skills 列表，列出可以用斜杠调用的技能。状态为 `user-only` 的技能会在名称右侧标出 `user-only`；选择一项会把 `/名称 ` 插入输入框，再补充本次的文本即可。在 dcl 中用 `/skills state` 设置的状态同样作用于 Desktop，两处使用数据目录中的同一份技能状态，设为 `off` 的技能不会出现在这里。技能状态、`/plugins` 面板和用量查看见[技能与插件面板](/cli/skills)。

连接器入口需按具体服务配置，Skill 文本不能替代连接凭据。

Skill 使用同一套会话执行与持久化流程。切换页面或断开流式观察连接不会停止后台执行；需要结束任务时使用会话的停止按钮，已保存的执行记录仍可查看。

## MCP、连接器与插件

- **MCP**：在“自定义 → MCP”添加、编辑、启动或停止服务，并展开工具列表。管理操作需在桌面客户端执行，详见[MCP 服务](../configuration/mcp.md)。
- **连接器**：查看 GitHub 连接状态，并按页面提示连接或断开；Google Drive 的连接能力尚未开放。
- **插件**：浏览网页工具、代码工具、AI 模型、文件工具、通信协作和数据分析分类。搜索框按分类名称与描述筛选。当前为分类浏览，暂不支持插件安装和启用。

![设置内的自定义与插件分类](/customize-settings-plugins.png)

界面验证过程、截图范围与结果见[自定义入口验证](../development/customize-verification.md)。

## 导入与维护

自定义页包含上传入口。导入前检查来源和支持格式，导入后核对名称、说明及正文；不要假设任意压缩包或其他工具的 Skill 格式都兼容。

流程变化后更新正文，用相同示例复测。只在当前会话提出要求，不一定会修改已保存的 Skill。

## 提示词

自定义页的**提示词**决定模型收到什么。修改后点击保存，下一次对话请求开始生效。Desktop 和 dcl 共用这些设置。

提示词和工具是两个独立入口，各自保存自己那一部分：在一页改了没保存就切到另一页保存，改动不会被一起提交；回到原来那页时草稿还在，可以继续保存。

草稿保留适用于提示词和工具之间连续切换。离开自定义页或关闭应用前，请分别保存需要保留的修改；重新打开时显示已保存的内容。

“完全替换”模式的提示词不能为空，清空后该页不能保存，但不会阻止工具页保存自己的修改。保存成功的提示只属于当前保存的页面。

![提示词页面](/desktop-customize-prompt.png)

**系统提示词**有三种使用方式：

- 使用内置提示词：可以展开查看完整内容。
- 在内置提示词后追加：保留内置行为，再加上你的规则。
- 完全替换内置提示词：编辑框从内置内容开始，改错了可以一键恢复。工作目录、操作系统等环境信息仍会自动附加。

## 工具

自定义页的**工具**决定模型能用什么。修改后点击保存，下一次对话请求开始生效。

**内置工具**每个都有两个独立开关，互不影响：

- **启用**：默认加载，每次模型请求都带上这个工具的定义。
- **按需加载**：允许模型通过 `ToolSearch` 在需要时加载它，不需要先打开“启用”。

两个都关时工具完全不可用；只关“启用”时模型仍能搜索到它。默认只有核心工具两个开关都打开，包括 `Bash`、`Read`、`Write`、`Edit`、`Grep`、`Glob`、`Skill`、`ToolSearch`、`AskUserQuestion`、计划相关工具，以及后台任务查看和停止。其他工具默认只开“按需加载”，标记为“默认核心”的工具也可以修改。工具的说明也可以修改，用来调整模型何时使用它，随时可以恢复默认。

以前关闭过的内置工具读作“启用关、按需加载开”，模型仍可搜索到它。只有**工具页**保存时才会整理这些旧条目，把它们折算成两个开关；保存提示词不会改动工具设置。两个页面各自保存，另一页未保存的修改会继续保留。

![内置工具的开关和说明](/desktop-customize-tools.png)

调整过工具后，页面会按当前保存的值显示：

![保存后的工具状态](/desktop-customize-tools-saved.png)

**自定义工具**把你的命令变成模型可以调用的工具。填写名称、说明、命令和输入参数的 JSON Schema，例如：

```json
{
  "type": "object",
  "properties": { "order_id": { "type": "string" } },
  "required": ["order_id"]
}
```

模型调用时，命令在当前工作目录运行：参数以 JSON 传入标准输入和环境变量 `TOOL_INPUT`，标准输出就是工具结果，退出码非 0 时错误输出会交给模型。默认超时 120 秒，可以修改。

![添加自定义工具](/desktop-customize-add-tool.png)

命令以当前用户的权限运行，和其他工具一样经过[权限审批](/desktop/configuration/permissions)。
